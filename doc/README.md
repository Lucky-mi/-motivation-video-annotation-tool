## 🔑 核心发现总结

### ✅ 优秀设计

1. **信号量并发控制**: 使用 `asyncio.Semaphore` 精确控制下载和审核并发
2. **清晰的关注点分离**: 下载、审核、统计各司其职
3. **完善的容错机制**: 重试、验证、速率限制检测
4. **灵活的配置**: 命令行参数、配置文件、环境变量

### ⚠️ 关键问题

1. **混合同步/异步睡眠**: `time.sleep` 阻塞事件循环
   - 位置: `content_filter.py:69`, `downloader.py:94`
   - 影响: 降低并发效率

2. **batch_check 事件循环滥用**: 在线程中创建新循环
   - 位置: `content_filter.py:396-407`
   - 影响: 资源泄漏 (好在未被使用)

3. **统计字段缺失**: `review_failed` 未初始化
   - 位置: `run_async.py:23`
   - 影响: 运行时可能出错

## 💡 常见问题

### Q: 为什么会出现 WinError 10055?
A: Windows 系统端口资源有限,高并发下会耗尽。建议:
- 降低并发数 (download=2, review=3)
- 使用 `Connection: close` (已实现)
- 定期重启程序释放资源

### Q: 如何提高审核通过率?
A: 参考 [config/search_config.py](../config/search_config.py):
- 使用优化关键词 (KEYWORDS_REAL_OPTIMIZED)
- 调整 STRICT_MODE
- 查看被拒绝视频的 reason,调整筛选策略

### Q: 流水线模式比当前模式快多少?
A: 理论提升 40-50%,实际取决于:
- 下载和审核时间比例
- 网络和 API 稳定性
- 并发配置

### Q: 如何监控处理进度?
A: 可以:
- 使用 tqdm 进度条 (见优化建议第6节)
- 查看日志输出
- 检查统计信息
