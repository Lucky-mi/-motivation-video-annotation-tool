```

│
└─ review_sem (Semaphore)
   └─ 信号量大小: 3 (可配置)
      └─ 限制同时审核的视频数量


并发执行示例:

时间轴 →
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

审核池 (3并发):
Video 1: ──────── [██████████████] ──────

## 3. 处理流水线

### 3.1 当前实现 (串行模式)

```
单个视频的处理流程:

    开始
     │
     ▼
┌──────────────────┐
│ 等待下载槽位可用  │  ← download_sem.acquire()
└──────────────────┘
     │
     ▼
┌──────────────────┐
│  下载视频         │  ← 使用 run_in_executor
│  (30-60秒)       │     包装同步的 yt-dlp
└──────────────────┘
     │
     ▼
┌──────────────────┐
│ 释放下载槽位      │  ← download_sem.release()
└──────────────────┘
     │
     ▼
┌──────────────────┐
│ 等待审核槽位可用  │  ← review_sem.acquire()
└──────────────────┘
     │
     ▼
┌──────────────────┐
│  AI 审核视频      │  ← 真正的异步操作
│  (40-80秒)       │     await check_video_content()
└──────────────────┘
     │
     ▼
┌──────────────────┐
│ 释放审核槽位      │  ← review_sem.release()
└──────────────────┘
     │
     ▼
┌──────────────────┐
│ 保存结果/删除文件 │
└──────────────────┘
     │
     ▼
    结束


特点:
✅ 实现简单
✅ 逻辑清晰
⚠️ 单视频内串行 (下载完才审核)
⚠️ 资源利用率不是最优
```

## 5. 异步执行模型

### 5.1 事件循环视图

```
asyncio Event Loop
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌──────────────────────────────────────────────┐
│             Ready Queue (就绪队列)            │
│  [Task1, Task2, Task3, ...]                  │
└──────────────────────────────────────────────┘
              │
              ▼
┌──────────────────────────────────────────────┐
│          Task Scheduler (调度器)             │
│  - 选择下一个 Ready 的 Task                  │
│  - 执行直到遇到 await                        │
└──────────────────────────────────────────────┘
              │
    ┌─────────┴─────────┐
    │                   │
    ▼                   ▼
┌─────────┐      ┌──────────────┐
│继续执行  │      │ 等待 I/O      │
│(CPU密集) │      │ (网络/磁盘)  │
└─────────┘      └──────────────┘
    │                   │
    │                   ▼
    │         ┌────────────────┐
    │         │ Waiting Queue  │
    │         │  (等待队列)    │
    │         └────────────────┘
    │                   │
    │                   │ I/O 完成
    │                   ▼
    └─────────────→ Ready Queue


示例: 下载视频的执行流程

Task: download_video(video1)
│
├─ await download_sem.acquire()
│  └─ [等待] 如果没有可用槽位 → Waiting Queue
│  └─ [就绪] 获得槽位 → 继续执行
│
├─ loop.run_in_executor(download_from_url, ...)
│  └─ [等待] 下载进行中 → Waiting Queue
│  └─ [I/O完成] 下载完成 → Ready Queue
│
└─ return result
```

## 6. 错误处理流程

```
异常处理机制:

┌─────────────────────┐
│  执行任务            │
└─────────────────────┘
          │
          ▼
     ┌──────┐
     │ 成功? │
     └──────┘
       │   │
    Yes│   │No
       │   ▼
       │ ┌──────────────────┐
       │ │ 捕获异常         │
       │ └──────────────────┘
       │   │
       │   ▼
       │ ┌──────────────────┐      Yes
       │ │ 可重试的错误?     │────────┐
       │ └──────────────────┘        │
       │   │ No                      │
       │   │                         ▼
       │   │                 ┌──────────────┐
       │   │                 │ 等待重试延迟  │
       │   │                 │ (指数退避)   │
       │   │                 └──────────────┘
       │   │                         │
       │   │                         ▼
       │   │                 ┌──────────────┐
       │   │                 │ 重试次数 < 3? │
       │   │                 └──────────────┘
       │   │                   │          │
       │   │                 Yes│         │No
       │   │                   │          │
       │   │                   └─→ 重试   │
       │   │                              │
       │   ▼                              ▼
       │ ┌──────────────────────────────────┐
       │ │ 记录错误 (stats, log)            │
       │ └──────────────────────────────────┘
       │   │
       │   ▼
       │ ┌──────────────────────────────────┐
       │ │ return None / False              │
       │ └──────────────────────────────────┘
       │   │
       ▼   ▼
┌──────────────────┐
│ 继续下一个任务    │
└──────────────────┘


错误类型分类:

1. 可重试错误:
   - 网络超时
   - 速率限制 (HTTP 429)
   - 临时服务不可用
   - 套接字错误 (WinError 10055)

2. 不可重试错误:
   - 视频不存在 (404)
   - 视频被删除
   - 格式不支持
   - 权限错误

3. 严重错误:
   - API Key 无效
   - 配置错误
   → 应该立即停止整个批处理
```

## 7. 资源管理

```
资源池管理:

┌─────────────────────────────────────────────┐
│            线程池 (ThreadPoolExecutor)       │
│  - 默认大小: CPU核心数 * 5                  │
│  - 用于: 包装同步的 yt-dlp 下载              │
│  - 生命周期: 跟随 Event Loop                │
└─────────────────────────────────────────────┘
                    ▲
                    │ run_in_executor()
                    │
┌─────────────────────────────────────────────┐
│          Download Semaphore (信号量)         │
│  - 大小: 2 (配置)                           │
│  - 作用: 限制同时下载数                     │
│  - 避免: 带宽竞争、端口耗尽                 │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│           Review Semaphore (信号量)          │
│  - 大小: 3 (配置)                           │
│  - 作用: 限制同时审核数                     │
│  - 避免: API限流、内存溢出                  │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│          网络连接池 (yt-dlp 内部)            │
│  - HTTP 连接复用                            │
│  - 配置: Connection: close (强制关闭)       │
│  - 原因: 避免 Windows 端口耗尽              │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│         文件句柄 (自动管理)                  │
│  - 使用 with 语句自动关闭                   │
│  - cv2.VideoCapture: 及时 release()         │
│  - genai.upload_file: 处理完删除云端文件    │
└─────────────────────────────────────────────┘


资源泄漏风险点:

⚠️ 高风险:
1. ThreadPoolExecutor 未正确关闭
   → 使用 asyncio 默认 executor (自动管理)

2. Gemini 云端文件未删除
   → 在 finally 块中调用 delete_file()

3. 视频文件句柄未释放
   → 使用 cap.release()

⚠️ 中风险:
1. 大量协程同时创建
   → 使用信号量限制

2. JSON 文件频繁读写
   → 考虑改用数据库 (长期优化)
```

      ├─ ③ AI 审核 (40-80s/个)

  搜索 (4%)  │ 保存 (1%)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

优化策略:

1. AI 审核 (最大瓶颈):
   ✓ 提高并发 (review_workers: 3→5)
   ✓ 使用更快的模型 (gemini-2.0-flash)
   ✓ 批量上传 (如果 API 支持)

2. 下载视频:
   ✓ 提高并发 (download_workers: 2→3)
   ⚠️ 注意端口资源限制
   ✓ 使用代理池轮换

3. 搜索:
   ✓ 缓存搜索结果
   ✓ 预搜索 (提前准备队列)

4. 保存:
   ✓ 批量写入
   ✓ 使用数据库替代 JSON
```

## 11. 总结

### 关键设计模式

1. **异步协程 (Coroutine)**
   - `async def` 定义异步函数
   - `await` 等待异步操作
   - 非阻塞式 I/O

2. **信号量模式 (Semaphore)**
   - 限制并发数
   - 资源池管理
   - 避免过载

3. **线程池执行器 (Executor)**
   - 包装同步代码为异步
   - 避免阻塞事件循环
   - CPU 密集任务卸载

4. **流水线模式 (Pipeline)**
   - 解耦生产和消费
   - 提高资源利用率
   - 易于扩展

5. **重试与降级 (Retry & Fallback)**
   - 指数退避
   - 速率限制检测
   - 备用方案

### 性能关键点

- ✅ 合理的并发配置
- ✅ 避免同步阻塞
- ✅ 资源及时释放
- ✅ 错误正确处理
- ⚠️ 注意平台限制 (Windows 端口)

### 未来改进方向

1. **架构升级**
   - 生产者-消费者流水线
   - 分布式任务队列
   - 微服务拆分

2. **性能优化**
   - 批量操作
   - 缓存机制
   - 连接池复用

3. **可观测性**
   - 实时监控
   - 指标收集
   - 告警系统
